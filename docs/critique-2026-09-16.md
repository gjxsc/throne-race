# 🎯 throne-race 对抗性审查报告

> **审查对象**：`throne-race/index.html`（3842 行，单文件四人抢王座棋）
> **基线版本**：commit `1c90bf8`（火龙5箱掉落 + 兜底救助传送）
> **审查日期**：2026-09-16
> **审查方式**：全量代码通读 + 静态证据链推演 + 双独立盲审（游戏设计 17 条 / 交互体验 18 条）
> **环境说明**：node 不可用，自动化持久化扫描（detect.mjs / critique-storage.mjs）已跳过，以下发现均为手工坐实

**总评**：工程底子扎实（hostSim 权威联机、预分配 BFS、兜底救助），但存在 1 个数学上必然发生的系统性死亡 bug（同步模式天灾全灭）和若干激励扭曲的设计问题。当前状态像一个"机制密度很高但有几根承重柱是空的"的房子。

## 一、硬缺陷（静态证据链闭合）

### ✅ H1【P0】同步模式天灾系统整体失效——roundNum 永久冻结为 1 **（已修复，见第九节）**

**证据链（四步，每步已核实）**：

1. `L1304`：`if (turnIdx===0) roundNum++;` —— **全文件唯一的 roundNum 递增点**，位于 `nextTurn()` 内
2. `L714-720` / `L868-873`：同步模式走子/放墙都在调用 `nextTurn()` **之前** `return`
3. 全部 19 处 `setTimeout/setInterval` 与 roundNum 无关；`turnCount` 只用于日志序号（L3212），无任何 `turnCount→roundNum` 转换
4. 后果（同步模式下 `roundNum≡1`，全部数学必然）：

| 机制 | 死因 | 行号 |
|---|---|---|
| 天灾降临 | `1 % 3 !== 0` 恒真 | L1101 |
| 熔岩关火山喷发 | 开局 `volcanoNext=3~5`，`1 < 3` 恒真 | L548, L1051 |
| 沙漠关沙暴换位 | `roundNum>1` 恒假 | L974 |
| 塌陷恢复/火墙熄灭 | `end(=1+3) <= 1` 恒假 | L919-926 |
| 天灾倒计时 UI | 永远显示"还剩 2 回合"的假值 | L3152 |

**最讽刺的实锤**：开局规则文案 L3360 明确写着 *"同步模式每 12 次行动降天灾"*（`disasterInterval*4`，即 4 行动=1 回合的心智模型）——**宣传的机制从未被实现**。

**✅ 修复方向（已确认）**：同步分支内在 `turnCount++` 后补 `if (turnCount % players.length === 0) roundNum++;`（约 3 行，与文案自洽），一处改动激活全部 5 个死机制。

### ✅ H2【P1】陷阱回出生点可叠人——triggerTrap 绕过了现成的回退逻辑 **（已修复，见第九节）**

`L1930` 直接 `teleport(p, SPAWN[p.color])`，而 `teleport`（L760-763）不检查占用。若玩家 B 先走到了 A 的出生角，A 踩陷阱 → 两棋叠格。而 `spawnDrop`（L1143-1153，上轮兜底救助已使用）已有"被占则滑落到最近空格"的正确逻辑。

**修复**：改一行 `spawnDrop(p)` 即可。

### ✅ H3【P1】走子/放墙的 tick 不对称——放墙成为"天灾闪避"手段 **（已修复，见第九节）**

同步分支：走子调 **7 个** tick（L718），放墙只调 **2 个**（L871，缺 blizzard/desert/worm/volcano/dragon）。玩家可刻意用放墙规避暴雪弹飞/沙虫/火龙推进——即使 H1 修好，这个不对称仍是节奏漏洞。

**修复**：抽 `tickAll()` 统一两处调用（约 5 行）。

### ✅ H4【P1】联机昵称注入面——4 处 innerHTML 未转义 **（已修复，见第九节）**

昵称从 `netNick`（maxlength=12）经 hello→seats→`players.name` 流转，仅在 `renderNetCard`（L3757）一处过 `escapeHtml`，而 L1379、L1533、L3136、L3544 直接 `${p.name}` 模板插入。恶意昵称可伪造弹窗/结算 UI，`<img onerror>` 可执行脚本。

**修复**：在 seats 接收端清洗一次（约 3 行），全链路免疫。

5. 选技倒计时可见且递减（30s → 28s 实测）
